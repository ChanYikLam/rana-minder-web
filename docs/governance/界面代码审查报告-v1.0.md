## 三、P1（明显功能/UX 缺陷）

### 3.1 系统性：202/accepted 异步响应未处理（涉及 15+ 页面）

`services/client.ts:119-127` 明确将 HTTP 202 与 `IFC-ERR-014` 映射为 `accepted` 分支并携带 taskId，但以下页面一律落入 else 误报"操作失败"或静默无反馈，异步受理被误判后可能引导用户重复提交：

- `recruitment/ApplicationPage.vue:292-298`（提交）、`:251-253`（存草稿）、`:139-143`（撤销）
- `recruitment/ReviewPage.vue:193-211, 216-230`（提交评价/发布结论）
- `recruitment/InvitationPage.vue:43-53, 57-68`（接受邀请）
- `recruitment/ApplicationsPage.vue:91-96, 111-116, 134-140`（操作/路径/发布结论）
- `recruitment/AdminRecruitmentListPage.vue:33-51`（强制结束，弹窗停留"正在执行..."）
- `recruitment/ActivityCreatePage.vue:72-83`
- `recruitment/InterviewManagePage.vue:119-133`、`InterviewSchedulePage.vue:68-92`
- `member/` 7 个页面（AppointmentPage:65-67、DepartmentApplyPage:54-55、MemberExitPage:59-60、MemberListPage:83-84、MemberProfilePage:40-41、MembershipInvitePage:79-110、TransitionPage:50-51）——统一置 `state='loading'` 且无轮询/重试，**页面永久卡加载**
- `form/FilePreviewPage.vue:33-35`（无限 loading）
- `organization/BatchOperationPage.vue` 等

**建议**：在 `client.ts` 或 `PageStateBoundary` 层统一消费 `accepted`（轮询 taskId / 降级提示），各页删除重复的 else 误报分支。
