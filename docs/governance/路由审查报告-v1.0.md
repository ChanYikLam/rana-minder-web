## 三、守卫决策链审查（guard.ts 148 行）

职责划分清晰，均为正向决策：

1. **身份切换清上下文**：`workspace.currentUserId !== session.user?.id` 时清空工作空间缓存，杜绝串身份。
2. **根路径落点**：未登录 → 登录页；已登录按 `resolveLoginTarget`（资料门禁 > redirect > 工作空间看板 > 平台管理 > 个人中心）解析，store 上下文优先于会话快照；`/admin/clubs`、`/me/profile/required`、`/org/...` 分别映射到 P-ORG-01 / P-GEN-04 / path 跳转。
3. **认证链**：非公开路由未认证 → `P-IDN-01?redirect=<fullPath>`（redirect 经 `parseSameOriginRedirect` 同源校验，防开放重定向）。
4. **资料门禁**：`needsProfileGate` 时仅豁免 P-GEN-04 / P-IDN-02 三件套，其余一律弹回。
5. **admin 权限链**：`ADMIN_PERMISSIONS[to.name]` 查不到映射时**保守拒绝**（新增 admin 路由未登记即 403，防默认放行）。
6. **workspace 权限链**：缺 `clubId`/无映射/`loadWorkspace` 失败/权限不满足 → 一律 P-GEN-02。
7. **非工作空间页上下文同步**：会话有工作空间且 store 未加载或身份不符时按会话初始化，保持侧边栏可用。

各链路均有对应单测覆盖（含保守拒绝、多权限任一命中、store 优先等边界），`guard.test.ts` 39 用例全绿。

## 四、问题清单

### P2-1（一致性）`/explore` 缺 `tab` meta，路由名与展示语义相悖

- **位置**：`src/router/index.ts:22-26`、`src/pages/recruitment/PublicCatalogPage.vue:35`
- **现状**：`/explore`（name `P-REC-07-clubs`）未声明 `tab`，页面 `activeTab` 默认回退 `'activities'` → **访问 `/explore` 实际展示的是"活动"标签**，与"clubs"路由名及顶部 Logo 直达入口（`/explore`）的语义不符；`/explore/clubs` 才是社团标签页。
- **建议**：二选一 —— 给 `/explore` 补 `meta: { tab: 'clubs' }`（若默认应为社团页），或改名 `P-REC-07` 并把默认标签明确为 activities。同时核对 `PublicCatalogPage.vue:84-101` 的 `switchTab` 跳转语义。

### P2-2（健壮性）`workspacePermissionForRoute` 前缀匹配依赖键序

- **位置**：`src/router/permissions.ts:58-63`
- **现状**：前缀回退用 `Object.keys(WORKSPACE_PERMISSIONS).find(startsWith(`${key}-`))`，依赖**键插入顺序**与"精确匹配优先"约定。当前 31 条路由全部正确解析，但：
  - 语义易错位：`P-REC-02`（精确，面试职能三选一）与 `P-REC-02-applications`（前缀，仅 `club:recruitment:manage`）同模块不同口径；`P-MEM-03-manage`（精确，invite）与假想 `P-MEM-03-*` 变体（前缀，落入 `club:member:manage`）口径相反。
  - 新增 `P-REC-*`/`P-MEM-*` 变体时若误命中 `P-REC`/`P-MEM` 前缀，可能静默获得比预期更宽/更窄的权限（好在守卫对无映射是保守拒绝，方向安全）。
- **建议**：新增路由后强制走 `permissions.test.ts` 覆盖映射解析；或在映射表改用"最长前缀优先"（先按 `-` 切分逐级回退），消除键序依赖。

### P2-3（陈旧性）非工作空间页用 `session.permissions` 快照初始化 store

- **位置**：`src/router/guard.ts:131-144`
- **现状**：非工作空间页导航时，若 store 未加载，用 `session.permissions`（登录时的权限快照）seed 工作空间上下文。若登录后角色/权限在服务端变更（如被移出社团、降权），侧边栏会展示已失效的入口，点击后由守卫 `loadWorkspace` 重新拉取才弹 P-GEN-02。
- **影响**：非安全问题（守卫会重查），但存在"导航可见但点击 403"的体验窗口。
- **建议**：可接受（避免每页导航都发请求）；如需收紧，可在进入 `/org/*` 任意页后触发一次 `loadWorkspace` 刷新，或在权限变更提示（P-NTF-01 通知）回调中 `clearWorkspace`。

### P2-4（一致性）`ADMIN_PERMISSIONS` 部分条目归口偏宽

- **位置**：`src/router/permissions.ts:41-42, 44-45`
- **现状**：`/admin/joint`、`/admin/recruitment`、`/admin/clubs`、`/admin/joint/:jointId/close`、`/admin/clubs/wizard` 全部归 `platform:club:manage`，粒度以"页面"为单位。页面内高敏操作（强制关闭、删除社团、修复接入）依赖组件内 `PermissionGuard`/按钮级校验，路由层无法区分。
- **建议**：维持现状可接受（与 P-REC-02 的组件内二次校验同模式）；仅提示后续新增平台管理页时先登记 `ADMIN_PERMISSIONS`，否则守卫保守拒绝会表现为"403 幽灵页"。

### P2-5（健壮性）`isGroupActive` 前缀判定存在相邻模块误高亮风险

- **位置**：`src/layouts/components/WorkspaceNav.vue:32-34`
- **现状**：组激活判定 `route.path.startsWith(group.prefix)` 正确覆盖了本组子路径；但前缀不含尾部 `/` 约束 —— 例如新增 `/org/:clubId/statsx` 或 `/org/:clubId/joint2` 类路由会误命中 `stats`/`joint` 组高亮（当前路由表无此冲突）。
- **建议**：低风险防御性改进 —— 改为 `route.path === group.prefix || route.path.startsWith(`${group.prefix}/`)`，避免未来新增段名时静默误高亮。

### P3-1（文档）分区注释条数与实际条数不符

- **位置**：`src/router/index.ts:8, 58, 192, 381`
- **现状**：注释标注"公开路由（7条）/登录用户（21条）/工作空间（26条）/管理员（14条）"，实际为 **8 / 22 / 31 / 18** 条（随迭代新增未同步）。
- **建议**：更新注释，或在路由定义处直接以表格/计数工具生成，避免再次漂移。

### P3-2（UX）`/files/:fileId` 与 `/forbidden` 需要登录

- **位置**：`src/router/index.ts:179-190`
- **现状**：公开详情页（P-REC-08）中引用附件预览 `/files/:id`，游客点击会被弹到登录页。可能是有意设计（附件需登录），但公开页 URL 直达体验可考虑对"公开已发布活动"的附件放行，或提供明确的"登录后查看"提示。

### P3-3（死代码/UX）根路径 `P-GEN-00-root` 页面永不渲染；404 使用 public 布局

- **位置**：`src/router/index.ts:492-503`
- **现状**：`/` 注册为 NotFoundPage 但守卫（guard.ts:61-89）对该路径必然返回重定向，页面本体是死代码（保留仅为了给 vue-router 提供具名落点）。同时 `/:pathMatch(.*)*` 的 `layout: public` 使已登录用户输错 URL 时落到无侧边栏的公开布局。
- **建议**：前者保留并在注释说明"仅作守卫落点载体"；后者可考虑按登录态动态布局（404 时登录用户保留导航便于返回）。
